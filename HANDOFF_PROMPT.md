## Required behavior
1. **Extract:** Read verified-project-labeled Gmail threads; subjects, sender, body, and qualifying attachments (PDF, scanned images; handle or explicitly classify unsupported Excel/CSV files). Extract supplier, invoice/order/receipt references, issue date, job name/address, subtotal/tax/freight/discount/total, item descriptions, SKU, material/labor/subcontractor/equipment/mixed, quantity/unit/price, and detailed scope for lump sums. Preserve the original Gmail source link (billing-account-aware `Message-ID` search) and raw evidence. A missing quantity must not prevent cataloging the charge; it only prevents a trustworthy unit rate.
2. **Project attribution:** Use verified Gmail job labels (most recently 29 verified), compare normalized project name/address and email/attachment context, but don't process unlabeled/unverified job mail. Never quietly change an established project when references conflict.
3. **Line-first cataloging:** Record useful numeric observations even on documents historically called `SUPPORTING`. Distinguish **observed/reference prices** from **actual booked expenses**. Quotes, confirmations, packing slips, delivery evidence and payment confirmations should not automatically become actual expenses, but their reliably extracted unique priced lines should be visible as clearly marked provisional/reference data. Invoice, purchase receipt and credits represent actual financial transactions when evidenced. Never silently drop valid prices just because a document type suggests 'supporting'.
4. **Correlation/deduplication:** Use **75% project name/address similarity as a candidate comparison trigger**, not permission to suppress expenses. Also compare supplier, normalized invoice/order/receipt numbers, dates, totals, SKU/description, quantity/unit and amount. Deduplicate at document/transaction/**line-item** level with strong identity evidence. Delivery confirmation first / receipt second, receipt first / delivery second, repeated forwarding, one order with multiple legitimate invoices or partial shipments, changed/revised invoice and credits must be handled. If a corrected invoice replaces earlier amounts, preserve provenance and make the **net actual cost accurate**, rather than counting the whole invoice twice or blindly adding all changed lines. Escalate genuinely ambiguous financial overlaps; let independent purchases pass. Processing must be idempotent when run twice or retried after interruption.
5. **Price History:** Continuously rebuild from authoritative actual purchases, with separate clearly labeled provisional/reference observations where useful. Normalize SF/LF/EA/HR/CY/etc., keep compatible item/category/cost-type distinctions, unit costs and dates, supplier, evidence count, low/median/average/high/latest, source document provenance. Allow manual verified quantities and exclusions. Distinguish quoted/reference prices from trusted actual unit rates and don't auto-use provisional rates for estimating. Configurable confidence is currently **0.80** for document classification and rate capture; **0.75** is only a similarity review threshold. Three distinct comparable source documents were previously targeted for auto-suggesting rates; verify actual code and settings.
6. **Simple estimation:** Retain the personal-account `Estimate` sheet and Buildertrend cost-code export (the supplied 126-code master), but do not complicate or duplicate the price database. Keep actual vs provisional cost indicators clear. Material/labor/subcontractor/equipment separation, waste/markup and user rate override where existing.
7. **Reliability:** Live new mail runs about every 15 minutes; history currently has an hourly trigger and configurable source batch. User may later want approximately 8 source documents every 15 minutes. Preserve Gmail source ledger and verified labels, avoid duplicate billing/account ingestion, prevent overlapping triggers with locks, obey Google Apps Script runtime quotas, report retries/errors with clear logs, and correct any cursor/offset coverage gaps without reprocessing duplicate costs.
